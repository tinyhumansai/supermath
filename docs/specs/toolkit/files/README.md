# Files: the project workspace

- **Status:** Draft
- **Crate:** `supermath-files`
- **Parent:** [`../README.md`](../README.md)

Each project has a workspace on disk: a Lean package and a Python package,
side by side. Every tool that runs code (Lean checks, Python solvers,
counterexample searches) runs a **file in this workspace**, never a string
of source passed as an argument. Source gets there only through the four
`file_*` tools in this crate.

## Layout

```text
projects/<slug>/
├── lean/                       # a Lake package on the pinned Mathlib
│   ├── lakefile.toml           # generated
│   ├── lean-toolchain          # the Lean service's toolchain
│   └── Supermath/
│       ├── Sendov/Main.lean
│       └── Witnesses/…         # generated by lean_search_counterexample
└── python/                     # a Python package on the pinned solver env
    ├── pyproject.toml          # generated; no dependencies of its own
    └── work/
        ├── sendov_search.py
        └── witnesses/…         # generated by py_search_counterexample
```

The root is `SUPERMATH_PROJECTS` (default `./.supermath/projects`). The
project slug comes from the host, never from an argument. In compose the
`projects` volume is mounted by the agent, which writes, and by the `lean`
and `python` services, which run what was written.

## Why files, not source

- **A result names something re-checkable.** `lean_check` and `py_run`
  report a path and its `sha256`; anyone can run the same file again. A
  verdict about a string the model sent is about nothing anyone kept.
- **Tokens.** Work proceeds by small edits to files the agent does not
  re-send: `file_edit` replaces one `sorry`, or one function.
- **Composition.** Lean modules import each other, and Python modules
  import each other, so a lemma or a helper written once is used by the
  next file.
- **Sub-agents share state safely.** Writes carry `if_sha256`, so two
  turns editing the same file conflict loudly instead of silently
  overwriting each other.

## Path rules

A path is relative to the project root, and its first segment names the
language:

| Language | Pattern | May import |
| --- | --- | --- |
| Lean | `^lean/Supermath/[A-Z][A-Za-z0-9]*(/[A-Z][A-Za-z0-9]*)*\.lean$` | `Mathlib`, `Supermath.*` of this project |
| Python | `^python/work/[a-z][a-z0-9_]*(/[a-z][a-z0-9_]*)*\.py$` | the standard library, the [solver environment](../python/README.md#the-solver-environment), `work.*` of this project |

For every path: no `..`, no absolute paths, no symlinks followed out of
the project, UTF-8 only, 1 MB at most. Generated directories
(`Witnesses/`, `witnesses/`) are written only by the tools that own them.

Imports are checked by a parse at write time: a Lean `import` line or a
Python `import`/`from` statement naming anything outside the table is
`INVALID_INPUT`. The language services are the real boundary
([Lean](../lean/README.md#isolation), [Python](../python/README.md#isolation)); the
import check gives the caller an early, specific refusal.

## Writes

- **Atomic.** Write to a temporary file in the same directory, then
  rename.
- **Guarded.** Every write takes `if_sha256`: the digest the caller last
  saw, or `null` for a new file. A mismatch is `CONFLICT`.
- **Logged.** Every write is appended to `projects/<slug>/.log/writes.jsonl`
  with the path, old and new digests, the calling tool, and the turn's
  session id. Agentic tools read this log, not their child's reply, to
  learn what a turn wrote.

## Observers

`file_list` shows each file's last result: a Lean verdict or a Python run.
The files crate does not know those domains; it defines a trait each
domain implements, and the composition in `supermath-mcp` registers them:

```rust
pub trait FileObserver: Send + Sync {
    /// The language this observer reports on.
    fn language(&self) -> Language;
    /// The last result recorded for `path`, and the digest it was for.
    fn last_result(&self, path: &ProjectPath) -> Option<LastResult>;
}
```

## Tools

| Tool | Given → returns |
| --- | --- |
| [`file_write`](tools/file_write.md) | a path and its content → the file written, with its digest |
| [`file_edit`](tools/file_edit.md) | a file and exact replacements → the edited file's digest and changed lines |
| [`file_read`](tools/file_read.md) | a file and a line range → its numbered lines and digest, or its outline |
| [`file_list`](tools/file_list.md) | the project, optionally a directory → its files with their last results |

## Acceptance criteria

- Path rules: a test per refusal (`..`, absolute, symlink out, wrong
  language root, bad module name, forbidden import in each language) and
  per acceptance.
- `if_sha256`: new-file, match, and mismatch cases for both write tools.
- `file_edit` refuses an `old` string that matches zero or two times, and
  applies several edits all or none.
- The write log records every successful write and no refused one.
- `file_list` reports a stale result once the file's digest changes, using
  a fake observer.
